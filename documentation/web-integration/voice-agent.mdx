Paste this into your page. The script loads [`@trillet-ai/web-sdk`](https://www.npmjs.com/package/@trillet-ai/web-sdk) `1.9.1` and registers `<trillet-widget>`. A launcher floats in the bottom-right corner. There is no build step, and the API key stays off the page.

```html index.html
<script src="https://unpkg.com/@trillet-ai/web-sdk/dist/widget.umd.js" async></script>

<trillet-widget
  agent-id="your-agent-id"
  workspace-id="your-workspace-id"
></trillet-widget>
```

The same file is on jsDelivr: `https://cdn.jsdelivr.net/npm/@trillet-ai/web-sdk/dist/widget.umd.js`.

Click the launcher, then **Start a call**. The widget needs microphone permission and must be served over **HTTPS** (or localhost).

`agent-id` and `workspace-id` are the public credential pair. To mint the call on your server instead, swap `workspace-id` for [`signed-url-endpoint`](#secure-setup-recommended). For your own interface, use the [headless SDK](#custom-ui) (`TrilletAgent`).

## Before it will connect

<Steps>
  <Step title="Copy the Agent ID">
    In the Portal sidebar, open **Call Flows**. Each call flow card shows its **Agent ID**.
  </Step>
  <Step title="Copy the Workspace ID">
    Open the **workspace name dropdown** at the top of the sidebar. The Workspace ID is listed next to each workspace. The [secure setup](#secure-setup-recommended) does not need it.
  </Step>
  <Step title="Turn on public access">
    Open the call flow, go to the **Settings** tab, and turn **Public Access** on. Public calls are rejected while it is off.
  </Step>
  <Step title="Register a domain when you want to lock the origin">
    Add the site that embeds the widget under **Settings → Domain**.

    The public web-call path allows every origin until the workspace registers its first domain. That first domain turns enforcement on, and calls from other origins are rejected. See [Domain allowlisting](#domain-allowlisting).
  </Step>
</Steps>

<Warning>
  `workspace-id` and `agent-id` are visible in page source. Never put your API key in the page. Use the [secure setup](#secure-setup-recommended) for a public site.
</Warning>

### React

`<TrilletWidget>` is the same element, with camelCase props:

```bash
npm install @trillet-ai/web-sdk
```

```tsx App.tsx
import { TrilletWidget } from '@trillet-ai/web-sdk/widget';

export default function App() {
  return (
    <TrilletWidget
      agentId="your-agent-id"
      workspaceId="your-workspace-id"
    />
  );
}
```

<Note>
  In Next.js the widget must render in a **client component** (add `'use client'`). It registers a browser custom element and cannot run during server rendering.
</Note>

## Secure setup (recommended)

In the secure flow your backend creates the call using your API key, and the browser only receives a short-lived LiveKit room token. **Your API key never reaches the browser**, and visitors can't extract anything reusable from your page.

<Steps>
  <Step title="Create a token endpoint on your backend">
    Install `@trillet-ai/web-sdk` on your server and call `createCall()` from the Node-safe `/server` entry point. It performs the authenticated `POST https://api.trillet.ai/v1/api/web-call` request and returns the room details as JSON:

    <CodeGroup>

```javascript server.js (Express)
import express from 'express';
import { createCall } from '@trillet-ai/web-sdk/server';

const app = express();

app.get('/api/trillet-token', async (req, res) => {
  try {
    const roomDetails = await createCall({
      apiKey: process.env.TRILLET_API_KEY, // never expose this to the browser
      agentId: process.env.TRILLET_AGENT_ID,
      mode: 'voice',
    });
    res.json(roomDetails);
  } catch (err) {
    res.status(500).json({ error: 'Failed to start call' });
  }
});
```

```typescript route.ts (Next.js App Router)
import { createCall } from '@trillet-ai/web-sdk/server';

// app/api/trillet-token/route.ts
export async function GET() {
  try {
    const roomDetails = await createCall({
      apiKey: process.env.TRILLET_API_KEY!, // never expose this to the browser
      agentId: process.env.TRILLET_AGENT_ID!,
      mode: 'voice',
    });
    return Response.json(roomDetails);
  } catch (err) {
    return Response.json({ error: 'Failed to start call' }, { status: 500 });
  }
}
```

    </CodeGroup>

    `createCall()` accepts:

    | Option | Type | Required | Description |
    | --- | --- | --- | --- |
    | `apiKey` | `string` | Yes | Your Trillet API key. Server-side only. |
    | `agentId` | `string` | Yes | The agent (call flow) to connect to. |
    | `mode` | `'voice' \| 'text'` | No | Session modality. Defaults to voice. |
    | `variables` | `object` | No | Dynamic variables passed to the agent. |
    | `callbackUrl` | `string` | No | Webhook called when the call ends. |

    It resolves to a `TrilletRoomDetails` object — return it to the browser as-is:

```json Response (TrilletRoomDetails)
{
  "connection": { "url": "wss://...", "token": "..." },
  "call_id": "...",
  "room_name": "...",
  "status": "...",
  "display": {
    "agent_name": "Support Agent",
    "call_flow_name": null,
    "workspace_name": "Acme Inc"
  }
}
```
  </Step>
  <Step title="Point the widget at your endpoint">
    Replace `workspace-id` with `signed-url-endpoint`. The widget performs a `GET` request to your endpoint **at call-start** (not at page load, so tokens can't expire while the page sits idle) and joins the room with the response:

    <Tabs>
      <Tab title="HTML / CDN">
```html index.html
<script src="https://unpkg.com/@trillet-ai/web-sdk/dist/widget.umd.js" async></script>

<trillet-widget
  agent-id="your-agent-id"
  signed-url-endpoint="https://yoursite.com/api/trillet-token"
></trillet-widget>
```
      </Tab>
      <Tab title="React / Next.js">
```tsx App.tsx
import { TrilletWidget } from '@trillet-ai/web-sdk/widget';

export default function App() {
  return (
    <TrilletWidget
      agentId="your-agent-id"
      signedUrlEndpoint="/api/trillet-token"
    />
  );
}
```

        React also supports two JS-only credential props that can't be expressed as HTML attributes: `getRoomDetails` (an async function invoked at call-start — useful when your fetch needs auth headers) and `roomDetails` (a static, pre-minted object):

```tsx App.tsx
<TrilletWidget
  agentId="your-agent-id"
  getRoomDetails={async () => {
    const res = await fetch('/api/trillet-token', {
      headers: { Authorization: `Bearer ${session.token}` },
    });
    return res.json();
  }}
/>
```
      </Tab>
    </Tabs>

    <Warning>
      Anyone who can reach your token endpoint can start calls billed to your workspace. Protect it with your own session auth, rate limiting, or bot checks — see [Abuse protection](#abuse-protection).
    </Warning>
  </Step>
  <Step title="Or join from your own UI (headless)">
    If you're not using the widget, fetch the same room details in the browser and pass them to `TrilletAgent.joinRoom()` — see [Custom UI](#custom-ui).
  </Step>
</Steps>

When multiple credential paths are configured, the widget resolves them in priority order: `signed-url-endpoint` / `getRoomDetails` → `roomDetails` → `workspace-id`. If none is set, the widget throws an error when a call is started.

## Configuration reference

All configuration is set as **kebab-case HTML attributes** on `<trillet-widget>`, or as **camelCase props** on the React `<TrilletWidget>` wrapper. Attributes are reactive — changing one re-renders the widget.

### Credentials

| Attribute | React prop | Description |
| --- | --- | --- |
| `agent-id` | `agentId` | **Required.** The agent (call flow) to connect to. |
| `signed-url-endpoint` | `signedUrlEndpoint` | URL of your token endpoint. Fetched with `GET` at call-start; must return `TrilletRoomDetails` JSON. The secure default. |
| — | `getRoomDetails` | JS-only. Async function invoked at call-start that returns `TrilletRoomDetails`. |
| — | `roomDetails` | JS-only. Static, pre-minted `TrilletRoomDetails` object. The token may expire between page load and the visitor clicking start — prefer `signed-url-endpoint`. |
| `workspace-id` | `workspaceId` | Public path: the browser calls Trillet's public endpoint directly. Use with `agent-id`. |

### Behavior

| Attribute | React prop | Default | Description |
| --- | --- | --- | --- |
| `mode` | `mode` | `voice` | `voice`, `text`, or `both`. In `both`, the visitor picks a modality and can switch mid-session (transcript and timer carry over). |
| `variables` | `variables` | — | Dynamic variables passed to the agent. JSON string as an attribute, plain object as a prop. Alias: `dynamic-variables` / `dynamicVariables`. |
| `max-call-duration` | `maxCallDuration` | — | Seconds. Shows a countdown and ends the call locally when it hits zero. UX only — real duration limits are enforced server-side. |
| `recaptcha-site-key` | `recaptchaSiteKey` | — | Google reCAPTCHA v2 site key. See [reCAPTCHA](#recaptcha-optional-bring-your-own). |
| `recaptcha-text` | `recaptchaText` | `Verify you are human to start` | Prompt shown above the reCAPTCHA checkbox. |

### Appearance

| Attribute | React prop | Default | Description |
| --- | --- | --- | --- |
| `placement` | `placement` | `bottom-right` | `top-left`, `top`, `top-right`, `bottom-left`, `bottom`, `bottom-right`. |
| `variant` | `variant` | `compact` | `compact` or `expanded` (also accepts `tiny`/`full`). The visitor can toggle between them from the panel header. |
| `dismissible` | `dismissible` | `false` | Adds a close button to the panel. Closing during a call ends it. |
| `avatar` | `avatar` | — | Image URL rendered inside the orb (and launcher). Alias: `avatar-image-url` / `avatarImageUrl`. |
| `avatar-orb-color-1` | `orbColor1` | `#2792dc` | First color of the animated orb gradient. |
| `avatar-orb-color-2` | `orbColor2` | `#9ce6e6` | Second color of the orb gradient. |
| `orb-color` | `orbColor` | — | Legacy single-color alias of `avatar-orb-color-1`. |

### Identity and branding

| Attribute | React prop | Description |
| --- | --- | --- |
| `agent-name` | `agentName` | Overrides the agent name in the header title. |
| `call-flow-name` | `callFlowName` | Overrides the call flow name in the header title. |
| `workspace-name` | `workspaceName` | Overrides the workspace name in the header title. |
| `brand-logo` | `brand.logo` | Your logo, shown in the panel header's brand slot. |
| `brand-color` | `brand.primaryColor` | Accent color for buttons and the launcher. |
| `brand-name` | `brand.name` | A small brand label next to the logo — **not** the panel title. |

<Note>
  In React the three `brand-*` attributes are a single `brand` object prop: `brand={{ logo: '...', primaryColor: '#16a34a', name: 'Acme' }}`.
</Note>

### Copy overrides

Every visible string in the widget can be replaced:

| Attribute | React prop | Default |
| --- | --- | --- |
| `action-text` | `actionText` | — (launcher label and idle status; falls back to the start button label) |
| `start-call-text` | `startCallText` | `Start a call` (`Start chat` in text mode) |
| `end-call-text` | `endCallText` | `End call` (`End chat` in text mode) |
| `message-text` | `messageText` | `Message` (the text entry point in `mode="both"`) |
| `switch-to-text-text` | `switchToTextText` | `Switch to text mode` |
| `switch-to-voice-text` | `switchToVoiceText` | `Switch to voice mode` |
| `listening-text` | `listeningText` | `Listening…` |

| `expand-text` | `expandText` | `Expand` |
| `collapse-text` | `collapseText` | `Collapse` |

### Methods

The element exposes an imperative API for driving the widget from your own code:

```javascript
const widget = document.querySelector('trillet-widget');

await widget.startConversation();      // or startConversation('text') in mode="both"
widget.endConversation();
```

| Method | Description |
| --- | --- |
| `startConversation(modality?)` | Opens the panel and starts a session. The optional `'voice' \| 'text'` argument picks the modality in `mode="both"`. |
| `endConversation()` | Ends the active session. |

`startCall()` / `endCall()` still exist as deprecated aliases — use the `Conversation` names in new code.

### Events

The element dispatches DOM `CustomEvent`s (bubbling and composed); the React wrapper forwards them to callback props:

| DOM event | React prop | `detail` / argument |
| --- | --- | --- |
| `conversationStarted` | `onConversationStart` | — |
| `conversationEnded` | `onConversationEnd` | Duration in seconds |
| `error` | `onError` | `Error` |
| `transcript` | `onTranscript` | Array of transcript entries |

```javascript
const widget = document.querySelector('trillet-widget');

widget.addEventListener('conversationStarted', () => console.log('Call started'));
widget.addEventListener('conversationEnded', (e) => console.log(`Lasted ${e.detail}s`));
widget.addEventListener('error', (e) => console.error(e.detail));
```

`call-start` / `call-end` (and `onCallStart` / `onCallEnd`) still fire as deprecated back-compat aliases.

## Branding

The widget is **blank and unbranded by default** — there is no "Powered by Trillet" badge, no Trillet logo, and no default title. What renders in the header is entirely yours to control.

**The panel title** identifies who the visitor is talking to. It resolves through an identity chain — the first non-empty value wins:

1. `agent-name` (your override) → backend agent name
2. `call-flow-name` (your override) → backend call flow name
3. `workspace-name` (your override) → backend workspace name

The backend values arrive when the call connects; setting any override attribute makes the title render immediately, before the first call.

**Your brand identity** lives in a separate slot above the title: `brand-logo` renders your logo, `brand-name` renders a small subordinate label next to it (it is never used as the title), and `brand-color` sets the accent color used by buttons and the launcher.

```html
<trillet-widget
  agent-id="your-agent-id"
  signed-url-endpoint="/api/trillet-token"
  agent-name="Ava"
  brand-logo="https://yoursite.com/logo.svg"
  brand-name="Acme Support"
  brand-color="#16a34a"
  avatar-orb-color-1="#16a34a"
  avatar-orb-color-2="#bbf7d0"
></trillet-widget>
```

## Abuse protection

Public-facing call buttons attract bots and freeloaders. Trillet layers several protections; use them together.

### Domain allowlisting

Public calls that use `workspace-id` are origin-checked on the public web-call path:

- With **no domains registered**, every origin is allowed.
- After the **first domain** is registered, enforcement turns on and other origins are rejected.
- Trillet-hosted demo links, `localhost`, and `127.0.0.1` stay allowed, so Portal demos and local development keep working.

In the Portal, turn **Public Access** on from the call flow **Settings** tab, and add the embedding site under **Settings → Domain**. You need permission to edit the workspace to change the domain list.

Trillet also rate-limits the public endpoint per IP, per workspace, and per browser fingerprint. The secure flow is not origin-checked. It is protected by keeping the API key on your backend, and by whatever auth you put on your token endpoint.

### reCAPTCHA (optional, bring your own)

Pass your own Google **reCAPTCHA v2** site key and the widget shows a checkbox the visitor must tick before their first conversation:

```html
<trillet-widget
  agent-id="your-agent-id"
  signed-url-endpoint="/api/trillet-token"
  recaptcha-site-key="your-recaptcha-v2-site-key"
  recaptcha-text="Please verify you're human"
></trillet-widget>
```

- **Once per session** — after the visitor solves it, they can start, end, and restart conversations without being re-challenged.
- It also gates the imperative API: `startConversation()` opens the panel and waits for the checkbox instead of bypassing it.
- **Fails open** — if Google's script can't load (blocked, offline, CSP), the widget logs a warning and lets the call through rather than stranding the visitor.

<Warning>
  This is **client-side friction, not bot protection**. The solved token is never sent to Trillet and never verified on any server — a determined script can skip it entirely. For a real gate, verify a challenge on your own backend using the headless `onBeforeCall` hook or by putting the check inside your token endpoint.
</Warning>

### Custom gating with onBeforeCall

For real verification, use the headless SDK's `onBeforeCall` hook. It is awaited at the top of every call-start path (`startCall`, `startPublicCall`, `joinRoom`) **before any network request** — throw or reject to abort the call with nothing minted and nothing connected:

```javascript
import { TrilletAgent } from '@trillet-ai/web-sdk';

const agent = new TrilletAgent({
  agentId: 'your-agent-id',
  onBeforeCall: async () => {
    // e.g. send a reCAPTCHA/Turnstile token to YOUR server and verify it there
    const ok = await myServer.verifyHuman();
    if (!ok) throw new Error('Verification failed');
  },
});
```

A rejection propagates to the caller and is also emitted on the agent's `error` event. `onBeforeCall` is a `TrilletAgent` config option — the widget's equivalent gate is its reCAPTCHA checkbox.

## Custom UI

Use the headless `TrilletAgent` class when you want your own interface. This is the custom-UI path. The drop-in `<trillet-widget>` above is the default.

`startCall()` sends your API key, so it belongs on a server, not in the page. In the browser, fetch room details from [your token endpoint](#secure-setup-recommended) and call `joinRoom()`.

```javascript
import { TrilletAgent } from '@trillet-ai/web-sdk';

const agent = new TrilletAgent({
  agentId: 'your-agent-id',
  mode: 'voice',
});

agent.on('connected', ({ callId, display }) => {
  console.log('Connected to', display?.agent_name ?? 'agent', callId);
});
agent.on('assistantStartedSpeaking', () => console.log('Agent speaking…'));
agent.on('assistantStoppedSpeaking', () => console.log('Listening…'));
agent.on('transcriptUpdate', (transcripts) => {
  // Full transcript so far: [{ role: 'user' | 'assistant', text, ... }]
  render(transcripts);
});
agent.on('disconnected', () => console.log('Call ended'));
agent.on('error', (err) => console.error(err));

// Mint credentials on YOUR backend, then join — no API key in the browser.
const roomDetails = await fetch('/api/trillet-token').then((r) => r.json());
await agent.joinRoom(roomDetails);
```

`joinRoom()` makes no Trillet API call from the browser — it connects straight to the room your backend minted. Requesting microphone access happens here, so call it from a user gesture (button click) to satisfy browser autoplay/permission policies.

### Methods

| Method | Description |
| --- | --- |
| `startCall()` | **Server-side only.** Starts a call with your API key. Do not call it from the page. Prefer `createCall()` from `@trillet-ai/web-sdk/server`, then `joinRoom()` in the browser. |
| `startPublicCall()` | Browser public path. Same `workspaceId` + `agentId` pair as the paste snippet, with your own UI. |
| `joinRoom(roomDetails)` | Join a room minted by your backend's `createCall()`. The secure browser entry point. |
| `endCall()` | End the session and disconnect. |
| `toggleMicrophone(enabled)` | Mute (`false`) / unmute (`true`) the visitor's microphone. |
| `getTranscripts()` | Returns the transcript array accumulated so far. |
| `sendTextMessage(text)` | Send a chat message (text mode only). |
| `getBrowserFingerprint()` | Returns the browser fingerprint used for public-call limit tracking. |

### Events

| Event | Payload | Description |
| --- | --- | --- |
| `connected` | `{ callId, roomName, display }` | Session is live. `display` carries the agent/call-flow/workspace names. |
| `disconnected` | — | Session ended. |
| `error` | `Error` | Something failed (connection, credentials, `onBeforeCall` rejection). |
| `transcriptUpdate` | `Transcript[]` | The full transcript so far, re-emitted on every change. |
| `message` | `{ text }` | A chat message from the agent (text mode). |
| `assistantStartedSpeaking` | — | The agent began speaking. |
| `assistantStoppedSpeaking` | — | The agent finished speaking. |
| `toolStarted` / `toolCompleted` | Tool call info | The agent is using a tool mid-conversation. |

<Note>
  Headless `mode` accepts `'voice'` or `'text'` only — the mid-session modality switch (`mode="both"`) is a widget feature.
</Note>

### Public calls from your own UI

<Warning>
  `startPublicCall()` uses the same public pair as the paste snippet (`workspace-id` and `agent-id`). Those IDs are visible in your JavaScript. For a custom UI that keeps the API key on the server, use [`joinRoom()`](#secure-setup-recommended) instead. Public calls are still limited by [domain allowlisting](#domain-allowlisting) and rate limits.
</Warning>

```javascript
import { TrilletAgent } from '@trillet-ai/web-sdk';

const agent = new TrilletAgent({
  workspaceId: 'your-workspace-id',
  agentId: 'your-agent-id',
  mode: 'voice',
});

await agent.startPublicCall();
```

Requirements: **Public Access** turned on for the call flow (**Settings** tab), and — once you want origin enforcement — your site added under **Settings → Domain**. Until the first domain is registered, any origin is allowed.

To keep the API key on the server, move call creation to [`createCall()`](#secure-setup-recommended) and replace `startPublicCall()` with `joinRoom(roomDetails)` (drop `workspaceId` from the constructor). On the widget, swap the `workspace-id` attribute for `signed-url-endpoint`.
