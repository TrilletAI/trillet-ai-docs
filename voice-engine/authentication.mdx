## Partner keys

Every Trillet OEM request is authenticated with a **partner key**, sent as a bearer token in the `Authorization` header:

```bash
curl https://api.trillet.ai/partner/v1/key \
  -H "Authorization: Bearer tpk_live_..."
```

- Keys start with `tpk_live_`. Keys can also be created with the `tpk_sandbox_` prefix, but sandbox tenants are not available yet, so use live keys.
- A key is shown **once**, when you create it. Trillet stores only a hash, so a lost key cannot be recovered. Create a new one and revoke the old one.
- Keys are created and revoked in the **OEM API** section of your account settings, by an owner or admin of your partner account. Each key shows its name, prefix, scopes, allowed tenants and when it was last used.
- A key acts as your partner account, not as a person, so it keeps working when staff leave. Keys do not expire. Revoking a key takes effect immediately.
- An account can hold up to 50 active keys.
- Send a partner key only in `Authorization`. Sending it in `x-api-key` is refused with `401`, and sending both a partner key and an `x-api-key` returns `400` `conflicting_credentials`.

<Warning>
  Treat partner keys like passwords. Keep them on your server, never in a browser or mobile app.
</Warning>

### Check a key

`GET /partner/v1/key` returns the key's mode, scopes, tenant restriction and your partner account. It needs no scope.

```json
{
  "object": "partner_key",
  "id": "6720c1f4a9b3e2d1c0f5a7b8",
  "mode": "live",
  "scopes": ["tenants:read", "tenants:write", "resources:read", "usage:read"],
  "tenantIds": [],
  "partner": {
    "id": "671f0e2a8c4d3b1a2e5f6c7d",
    "name": "Example Health",
    "maxTenants": 100,
    "tenantCount": 12
  }
}
```

`maxTenants` is the number of tenants your account may hold. Ask your account manager to raise it.

`tenantCount` is the number of tenants counted against `maxTenants`: every tenant your account holds that is `active`, `suspended` or `provisioning_failed`. It goes up when a tenant is created or restored and down when one is deleted, so deleted tenants are not counted, even while they can still be restored. It covers your whole account, not only the tenants a restricted key can see.

## Scopes

Give each key only the scopes it needs. A new key has every scope unless you choose fewer.

| Scope | Allows |
|---|---|
| `tenants:read` | List and read tenants |
| `tenants:write` | Create, update, suspend, resume, delete and restore tenants, and set tenant spend caps |
| `resources:read` | Read agents, call flows, node flows, knowledge bases, numbers, call history, workflows and recordings in tenants |
| `resources:write` | Create, change and delete those resources |
| `calls:write` | Start outbound calls, web calls and batch calls, and run or activate workflows |
| `numbers:write` | Buy, register and release phone numbers (buying costs money) |
| `events:read` | Read the event log and webhook endpoints |
| `webhooks:write` | Manage webhook endpoints, rotate secrets, send test events and redeliver events |
| `usage:read` | Read usage |
| `templates:read` / `templates:write` | Reserved for [templates](/voice-engine/templates) (planned). No endpoint uses them yet. |
| `sessions:write` | Reserved for [embedding](/voice-engine/embedding) (planned). No endpoint uses it yet. |

### Restricting a key to some tenants

A key can be **restricted to a list of tenants**, for example a key used by one regional team. A restricted key:

- sees only those tenants in lists, usage and the event log;
- gets `404` `tenant_not_found` for any other tenant on `/partner/v1` routes, and `403` `tenant_not_allowed` on standard routes;
- cannot manage webhook endpoints (`403` `key_restricted`), because endpoints receive events for every tenant.

## Calling standard endpoints for a tenant

A partner key can call a set of standard API endpoints on behalf of one of its tenants. Send the tenant ID in `x-workspace-id`:

```bash
curl https://api.trillet.ai/v1/api/agents \
  -H "Authorization: Bearer tpk_live_..." \
  -H "x-workspace-id: 6a9622d2c1e8f3a4b5d6e7f8"
```

Access is deny by default. Only the endpoints below are available to partner keys, each with the scope shown. Any other standard endpoint returns `403` `route_not_available`.

### Building an agent

Today a partner builds a tenant's agent through node flows:

1. `POST /v2/api/node-graphs` creates the node flow together with its agent and call flow. The flow starts as a draft. With a partner key, the new agent uses the model `platform-llm` unless the body names another allowed model in `llmModel` (an unknown model returns `400` `LLM_MODEL_INVALID`), and the call flow starts with speech responsiveness 10 and interruption sensitivity 5.5.
2. Edit it with `PUT /v2/api/node-graphs/{id}` or `PATCH /v2/api/node-graphs/{id}/draft`, and check it with `POST /v2/api/node-graphs/{id}/validate`.
3. `POST /v2/api/node-graphs/{id}/publish` makes it live. A flow must be published before it can take calls.
4. `GET /v2/api/node-graphs/{id}` returns the flow with `pathway`, which holds the call flow ID (`pathway._id`) and the agent ID (`pathway.agent`).
5. `PUT /v1/api/agents/{agentId}` sets the agent's voice, language, model and other agent settings.
6. `PATCH /partner/v1/tenants/{tenantId}/call-flows/{callFlowId}/settings` sets the greeting, speech timing, recording and call handling timers. See [Call flow settings](/voice-engine/call-flow-settings).
7. `POST /v1/api/agents/{agentId}/bind/{phoneNumberId}` assigns a number. See [Phone numbers](/voice-engine/phone-numbers#assign-a-number-to-an-agent).

Creating and updating simple prompt call flows (`POST` and `PUT /v1/api/call-flows`) is not available to partner keys yet.

### Not available yet

These return `403` `route_not_available` to a partner key:

- Creating and updating simple prompt call flows (`POST /v1/api/call-flows`, `PUT /v1/api/call-flows/{id}`). Build agents with node flows instead, and change basic settings with [Call flow settings](/voice-engine/call-flow-settings).
- Call-flow draft writes other than those listed above: creating a draft, autosave and publishing a draft (`.../drafts`, `.../drafts/autosave`, `.../drafts/{draftId}/publish`), and every other call-flow route not in the table.
- The `/v1/api/calls/recordings/*` routes. Use `GET /v2/api/recordings/{callHistoryId}` or the [recording download](/voice-engine/events#recordings).
- Routes that take a target workspace in the body, such as duplicating or moving a flow to another workspace, and sharing.
- Routes that take a user ID in the path.
- Third-party credentials: Google, GHL, Meta, bring-your-own voice keys and Google Sheets export.
- Public demo links, Slack and the prompt helper endpoints.
- Account, billing, wallet, team members and roles, domains, and API key management.

### Start an outbound call

`POST /v1/api/call` places an outbound call from one of the tenant's numbers. It needs `calls:write`.

```bash
curl -X POST https://api.trillet.ai/v1/api/call \
  -H "Authorization: Bearer tpk_live_..." \
  -H "x-workspace-id: 6a9622d2c1e8f3a4b5d6e7f8" \
  -H "Content-Type: application/json" \
  -d '{
    "to": "+15125550177",
    "call_agent_id": "6a9623aa1b2c3d4e5f6a7b8c",
    "dynamic_variables": { "customer_name": "Sam" },
    "metadata": { "crmLeadId": "L-1042" }
  }'
```

<ParamField body="to" type="string" required>
  The number to call, in E.164 format. Anything else returns `400` `INVALID_PHONE_NUMBER`.
</ParamField>
<ParamField body="call_agent_id" type="string" required>
  The agent to call with. Required unless you send `call_flow_id` instead. The agent's call flow must be live.
</ParamField>
<ParamField body="call_flow_id" type="string">
  A call flow ID, accepted in place of `call_agent_id`. If you send both, they must refer to the same agent, or the request returns `400` `AGENT_FLOW_MISMATCH`.
</ParamField>
<ParamField body="from_phone_number_id" type="string">
  The tenant number to call from. When omitted, one of the agent's numbers is chosen automatically.
</ParamField>
<ParamField body="dynamic_variables" type="object">
  A flat key-value object of variables for the call, for example `{"customer_name": "Sam"}`. Arrays are refused.
</ParamField>
<ParamField body="metadata" type="object">
  Your own data, stored with the call.
</ParamField>
<ParamField body="callback_url" type="string">
  A URL to receive webhook events about this call.
</ParamField>
<ParamField body="reject_outside_hours" type="boolean">
  `true` refuses the call with `409` `OUTSIDE_CALLING_HOURS` when it is outside the flow's calling hours, instead of queueing it for the next calling window. The `409` response includes `next_available_at` and `timezone`.
</ParamField>

A successful request returns `status: "success"` with `call_agent_id`, `callId` (the call history ID), `roomName` and `jobId`. The call is queued and dialled straight after. Refusals return `status: "error"` with `message`, `error` and, where there is one, `code`. A suspended tenant gets `403` `workspace_suspended`.

See [Initiate outbound call](/v1/api-reference/endpoints/calls/initiate-call) for the full reference. `POST /v1/api/calls/call` is an older route that takes only `agentId` and `toNumber`. Use `POST /v1/api/call`, which validates the number and accepts the fields above.

A tenant that is not yours returns `404` `tenant_not_found`, so a key can never confirm another partner's tenant IDs. Your own partner account is not a tenant: a partner key cannot use it as `x-workspace-id`.

<Note>
  The partner key check uses the [Trillet OEM error format](/voice-engine/conventions#errors). Once a request passes the check, the standard endpoint answers in its usual format.
</Note>

## Authentication errors

| Status | Code | Meaning |
|---|---|---|
| `400` | `conflicting_credentials` | Both a partner key and an `x-api-key` were sent |
| `400` | `tenant_required` | A standard endpoint was called without `x-workspace-id` |
| `400` | `invalid_tenant` | `x-workspace-id` is not a valid tenant ID |
| `401` | `partner_key_required` | A `/partner/v1` route was called without a partner key |
| `401` | `invalid_api_key` | The key is malformed, unknown or revoked |
| `401` | `partner_not_enabled` | Trillet OEM is not enabled for this account |
| `403` | `missing_scope` | The key lacks the scope this endpoint needs |
| `403` | `route_not_available` | The standard endpoint is not available to partner keys |
| `403` | `tenant_not_allowed` | The key is restricted and this tenant is not in its list (standard endpoints) |
| `404` | `tenant_not_found` | The tenant does not exist or is not yours |
| `429` | `rate_limited` | Too many invalid keys from your IP address in the last minute |
