---
title: "List Roles"
api: "GET /v1/api/roles-and-permissions/roles"
description: "Retrieve all roles available in your workspace, including the built-in system roles."
---

Requires the `role:view` permission in the workspace.

The response is a bare array. It contains the workspace's custom roles plus the four built-in system roles, `owner`, `admin`, `editor` and `viewer` (lowercase, `isSystem: true`). System roles have no `workspaceId`.

## Headers
<ParamField header="x-workspace-id" type="string" required>
Workspace identifier for the API.
</ParamField>

## Response Fields

<ResponseField name="_id" type="string">
Unique identifier for the role.
</ResponseField>

<ResponseField name="name" type="string">
Name of the role.
</ResponseField>

<ResponseField name="description" type="string">
Description of the role.
</ResponseField>

<ResponseField name="permissions" type="object">
Permissions grouped by category. Each key is a category and its value is the list of permission keys (e.g., `"agent": ["agent:view", "agent:edit"]`).
</ResponseField>

<ResponseField name="isSystem" type="boolean">
`true` for the built-in roles, which can't be edited or deleted.
</ResponseField>

<ResponseField name="workspaceId" type="string">
Workspace the role belongs to. Absent on system roles.
</ResponseField>

<ResponseField name="userIds" type="array of strings">
IDs of the users in this workspace who hold the role.
</ResponseField>

<ResponseField name="createdAt" type="string">
Timestamp when the role was created.
</ResponseField>

<ResponseField name="updatedAt" type="string">
Timestamp when the role was last updated.
</ResponseField>
