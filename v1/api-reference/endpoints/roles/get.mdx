---
title: "Get Role"
api: "GET /v1/api/roles-and-permissions/roles/{roleId}"
description: "Retrieve a specific role by its ID."
---

Requires the `role:view` permission in the workspace.

## Headers
<ParamField header="x-workspace-id" type="string" required>
Workspace identifier for the API.
</ParamField>

## Path Parameters

<ParamField path="roleId" type="string" required>
The unique identifier of the role. A well-formed ID that matches no role returns `404`. A value that isn't a valid ID returns `500`.
</ParamField>

## Response Fields

<ResponseField name="_id" type="string">
Unique identifier for the role.
</ResponseField>

<ResponseField name="name" type="string">
Name of the role.
</ResponseField>

<ResponseField name="description" type="string">
Description of the role.
</ResponseField>

<ResponseField name="permissions" type="object">
Permissions grouped by category. Each key is a category and its value is the list of permission keys.
</ResponseField>

<ResponseField name="isSystem" type="boolean">
`true` for the built-in roles (`owner`, `admin`, `editor`, `viewer`).
</ResponseField>

<ResponseField name="workspaceId" type="string">
Workspace the role belongs to. Absent on system roles.
</ResponseField>

<ResponseField name="createdAt" type="string">
Timestamp when the role was created.
</ResponseField>

<ResponseField name="updatedAt" type="string">
Timestamp when the role was last updated.
</ResponseField>

<Note>
  This endpoint doesn't return the role's users. Use [List Roles](/v1/api-reference/endpoints/roles/list), which includes `userIds` for each role.
</Note>
