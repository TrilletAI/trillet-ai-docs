---
title: "Update Knowledge Base"
api: "PUT /v1/api/knowledgebase/{id}"
description: "Update the name or description of an existing knowledge base."
---

Only `name` and `description` can be changed here. To change the content, use [Add Text](/v1/api-reference/endpoints/knowledge-base/add-text) or [Upload File](/v1/api-reference/endpoints/knowledge-base/upload-file).

## Headers
<ParamField header="x-workspace-id" type="string" required>
Workspace identifier for the API.
</ParamField>

## Path Parameters

<ParamField path="id" type="string" required>
The unique identifier of the knowledge base to update.
</ParamField>

## Request Body

<ParamField body="name" type="string">
Updated name for the knowledge base.
</ParamField>

<ParamField body="description" type="string">
Updated description for the knowledge base.
</ParamField>

## Response

`200` with a confirmation message. The updated knowledge base is not returned; call [Get Knowledge Base](/v1/api-reference/endpoints/knowledge-base/get) to read it back. Sending neither field also returns `200` and changes nothing.

<ResponseField name="message" type="string">
Always `Knowledge base updated successfully`.
</ResponseField>

## Errors

| Status | Body | When |
| --- | --- | --- |
| `400` | `{"message": "X-Workspace-ID header is required"}` | No `x-workspace-id` |
| `500` | `{"message": "Knowledge base not found or not accessible in this workspace."}` | No knowledge base with this ID in the workspace. This is currently a `500`, not a `404` |
| `500` | `{"message": "..."}` | Anything else, such as an empty `name` |

<ResponseExample>
```json
{
  "message": "Knowledge base updated successfully"
}
```
</ResponseExample>
