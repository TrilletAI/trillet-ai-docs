---
title: "Add Flow to Folder"
api: "POST /v1/api/flow-folders/{folderId}/flows"
description: "Put a call flow or message flow into a folder."
---

A flow can be in only one folder. If the flow is already in another folder, it is **moved**: it's removed from the old folder and added to this one in a single step.

### Headers

<ParamField header="x-workspace-id" type="string" required>
  The workspace the folder belongs to. Folders and flows in other workspaces are treated as not found.
</ParamField>

### Path Parameters

<ParamField path="folderId" type="string" required>
  The `_id` of the folder to add the flow to.
</ParamField>

### Request Body

<ParamField body="pathwayId" type="string" required>
  The `_id` of the call flow or message flow. It must be in the same workspace.
</ParamField>

<ParamField body="pathwayType" type="string" required>
  `call` or `message`. Must match the folder's `flowType`.
</ParamField>

### Response

The updated folder:

<ResponseField name="_id" type="string">
  The folder's unique identifier.
</ResponseField>

<ResponseField name="workspaceId" type="string">
  The workspace the folder belongs to.
</ResponseField>

<ResponseField name="name" type="string">
  The folder name.
</ResponseField>

<ResponseField name="color" type="string">
  The folder color, stored exactly as sent (default `#3498db`).
</ResponseField>

<ResponseField name="icon" type="string">
  The folder icon, stored exactly as sent (default `folder`).
</ResponseField>

<ResponseField name="flowType" type="string">
  `call` or `message`.
</ResponseField>

<ResponseField name="pathwayModel" type="string">
  `Pathway` for call folders, `MessagePathway` for message folders. Set by the server from `flowType`.
</ResponseField>

<ResponseField name="pathways" type="array">
  The `_id`s of the flows in the folder.
</ResponseField>

<ResponseField name="createdAt" type="string">
  When the folder was created (ISO 8601). Folders have no `updatedAt`.
</ResponseField>

### Errors

All folder errors use a `message` field, not `error`.

| Status | Body | When |
| --- | --- | --- |
| `400` | `{"message": "x-workspace-id header is required"}` | `x-workspace-id` missing or not a valid ID |
| `400` | `{"message": "Pathway type does not match folder type"}` | `pathwayType` missing or different from the folder's `flowType` |
| `400` | `{"message": "Pathway already exists in the folder"}` | The flow is already in this folder |
| `404` | `{"message": "Folder not found"}` | No folder with that ID in this workspace |
| `404` | `{"message": "Pathway not found"}` | No flow with that ID (of that type) in this workspace |
| `500` | `{"message": "..."}` | Unexpected server error |
