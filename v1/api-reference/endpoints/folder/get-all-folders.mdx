---
title: "Get All Folders"
api: "GET /v1/api/flow-folders"
description: "List every flow folder in the workspace."
---

Returns call and message folders together, newest first. Each folder lists only the IDs of its flows. Use [Get Folder Details](/v1/api-reference/endpoints/folder/get-folder-details) for the flows themselves.

### Headers

<ParamField header="x-workspace-id" type="string" required>
  The workspace the folder belongs to. Folders and flows in other workspaces are treated as not found.
</ParamField>

### Response

An array of folders. Each folder has these fields:

<ResponseField name="_id" type="string">
  The folder's unique identifier.
</ResponseField>

<ResponseField name="workspaceId" type="string">
  The workspace the folder belongs to.
</ResponseField>

<ResponseField name="name" type="string">
  The folder name.
</ResponseField>

<ResponseField name="color" type="string">
  The folder color, stored exactly as sent (default `#3498db`).
</ResponseField>

<ResponseField name="icon" type="string">
  The folder icon, stored exactly as sent (default `folder`).
</ResponseField>

<ResponseField name="flowType" type="string">
  `call` or `message`.
</ResponseField>

<ResponseField name="pathwayModel" type="string">
  `Pathway` for call folders, `MessagePathway` for message folders. Set by the server from `flowType`.
</ResponseField>

<ResponseField name="pathways" type="array">
  The `_id`s of the flows in the folder.
</ResponseField>

<ResponseField name="createdAt" type="string">
  When the folder was created (ISO 8601). Folders have no `updatedAt`.
</ResponseField>

### Errors

All folder errors use a `message` field, not `error`.

| Status | Body | When |
| --- | --- | --- |
| `400` | `{"message": "x-workspace-id header is required"}` | `x-workspace-id` missing or not a valid ID |
| `500` | `{"message": "..."}` | Unexpected server error |
