---
title: "Create Flow Folder"
api: "POST /v1/api/flow-folders"
description: "Create a folder for call flows or message flows in a workspace."
---

### Headers

<ParamField header="x-workspace-id" type="string" required>
  The workspace the folder belongs to. Folders and flows in other workspaces are treated as not found.
</ParamField>

### Request Body

<ParamField body="name" type="string" required>
  The folder name (for example `"Inbound Flows"`).
</ParamField>

<ParamField body="flowType" type="string" required>
  What the folder holds: `call` (call flows) or `message` (message flows). Can't be changed later.
</ParamField>

<ParamField body="color" type="string">
  Any string. It is stored and returned exactly as sent, with no validation or conversion, so send a hex color such as `#3B82F6`. Defaults to `#3498db`.
</ParamField>

<ParamField body="icon" type="string">
  Any string, stored as sent. The portal uses `folder`, `file`, `phone`, `headphone`, `voice` and `message`. Defaults to `folder`.
</ParamField>

### Response (201 Created)

<ResponseField name="_id" type="string">
  The folder's unique identifier.
</ResponseField>

<ResponseField name="workspaceId" type="string">
  The workspace the folder belongs to.
</ResponseField>

<ResponseField name="name" type="string">
  The folder name.
</ResponseField>

<ResponseField name="color" type="string">
  The folder color, stored exactly as sent (default `#3498db`).
</ResponseField>

<ResponseField name="icon" type="string">
  The folder icon, stored exactly as sent (default `folder`).
</ResponseField>

<ResponseField name="flowType" type="string">
  `call` or `message`.
</ResponseField>

<ResponseField name="pathwayModel" type="string">
  `Pathway` for call folders, `MessagePathway` for message folders. Set by the server from `flowType`.
</ResponseField>

<ResponseField name="pathways" type="array">
  An empty array for a new folder.
</ResponseField>

<ResponseField name="createdAt" type="string">
  When the folder was created (ISO 8601). Folders have no `updatedAt`.
</ResponseField>

### Errors

All folder errors use a `message` field, not `error`.

| Status | Body | When |
| --- | --- | --- |
| `400` | `{"message": "x-workspace-id header is required"}` | `x-workspace-id` missing or not a valid ID |
| `500` | `{"message": "FlowFolder validation failed: ..."}` | `name` or `flowType` missing, or `flowType` isn't `call` or `message`. These validation errors currently return `500`, not `400` |
