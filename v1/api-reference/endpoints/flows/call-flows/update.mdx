<ParamField body="welcomeMessage" type="string">
A shortcut that gives both directions, `Inbound` and `Outbound`, the same greeting type. For updates, prefer `settings.welcomeMessageConfig`: it can change one direction at a time and covers every greeting option. The value is case-sensitive:

- `aiFirst` or `ai_dynamic`: the AI writes the greeting. Saved as `aiFirst` (AI Generated in the editor).
- `customMessage` or `ai_custom`: the agent opens with the text in `customWelcomeMessage`. Saved as `customMessage` (Custom Message in the editor).
- `userFirst` or `user_initiated`: the agent waits for the caller to speak first. Saved as `userFirst` (Wait for Caller in the editor).

Any other value returns `400` with `code: "GREETING_TYPE_INVALID"`, and the flow is not changed.

The shortcut is saved into `settings.welcomeMessageConfig`, so `welcomeMessage` and `customWelcomeMessage` are not stored. You can also send both fields inside `settings`. If you send a field in both places, the top-level value wins. If the request also includes `settings.welcomeMessageConfig`, the shortcut is ignored.

If the shortcut fields you send at the top level, or inside `settings`, all have exactly the values the flow already has in that place, they are ignored. Some older flows still return these fields, so sending a Get Call Flow response back unchanged does not change the greeting, as long as the flow has no unpublished changes from the call flow editor (see the Note below). To change it, send a different value or use `settings.welcomeMessageConfig`.
</ParamField>

<ParamField body="customWelcomeMessage" type="string">
The text the agent says for a `customMessage` greeting, saved as `customMessage` in both directions. If you send non-blank text without `welcomeMessage`, the greeting type is set to `customMessage`. If you send `welcomeMessage: "customMessage"` without this field, each direction keeps the text it already has.

When a direction's greeting type is `customMessage`, its text must not be blank. Otherwise the request returns `400` with `code: "GREETING_TEXT_REQUIRED"`, and the flow is not changed.
</ParamField>

  <ParamField body="welcomeMessageConfig" type="object">
    How the agent opens a call, set separately for each direction. The keys `Inbound` and `Outbound`, the field names and the `selected` values are case-sensitive.

    - `Inbound` is used for calls received on the flow's phone number.
    - `Outbound` is used for calls the flow places and for web calls made with the Web SDK. A flow with `direction: "outbound"` only uses `Outbound`, and an older flow with `direction: "inbound"` uses `Inbound` for these calls too.
    - Test calls from the dashboard, and calls started with [Connect a Web Call](/v1/api-reference/endpoints/calls/web/connect), use `Inbound`, except on an outbound-only flow, where they use `Outbound`. Unless the flow is outbound-only, you can switch a dashboard test call to `Outbound`.

    Only what you send changes: a direction or field you leave out keeps its current value, and `null` leaves a value as it is. Values equal to the flow's live greeting are not checked again. If the flow has unpublished changes from the call flow editor, Get Call Flow returns that draft's greeting. Sending it back makes it the live greeting and checks it where it differs, so a draft Custom Message with blank text returns `400` with `code: "GREETING_TEXT_REQUIRED"`. A change is used from the flow's next call; nothing has to be published.

    `settings.welcomeMessage` and `settings.customWelcomeMessage` are the same shortcut as the top-level `welcomeMessage` and `customWelcomeMessage`.

    If any greeting input is not valid, the flow is not changed. The response is a `400` that lists every problem at once, with the body `{ "message", "code", "field", "errors" }`: `errors` has one message per problem, `message` joins them, and `code` and `field` describe the first one.

    - `400` with `code: "GREETING_TYPE_INVALID"`: `selected` is not `aiFirst`, `customMessage` or `userFirst`, or `welcomeMessage` is not one of its accepted values.
    - `400` with `code: "GREETING_FIELD_UNKNOWN"`: a direction key other than `Inbound` or `Outbound` (such as `inbound`), a direction field other than the five below, a greeting setting such as `welcomeMessageConfig` or `welcomeMessageDelay` sent outside `settings`, or a greeting-like name that the API does not use, such as `greeting` or `firstMessage`.
    - `400` with `code: "GREETING_VALUE_INVALID"`: `welcomeMessageConfig` or a direction is not an object, a text field (including `customWelcomeMessage`) is not a string, or `userFirstFallbackDelaySeconds` is not a number from 1 to 30.
    - `400` with `code: "GREETING_TEXT_REQUIRED"`: a direction's `selected` would be `customMessage` while its `customMessage` text is blank.

Optional concurrency check. Send the `updatedAt` you last read. If the flow has changed since then, the update is refused with `409` and nothing is saved.

<Note>
`settings` is merged into the stored settings: objects merge key by key, and a key you leave out keeps its value. **Arrays are replaced, not merged**: this applies to the top-level `webhooks` and `dynamicVariableCollections`, and to arrays inside `settings` such as `transfers`, `knowledgeBases`, `knowledgeBaseFiles` and `callSetting.reminderMessages`. `null` values are ignored.
</Note>

<Note>
If the flow has unpublished changes from the call flow editor, [Get Call Flow](/v1/api-reference/endpoints/flows/call-flows/get) returns the draft merged over the live flow. This endpoint writes to the live flow.
</Note>

<Note>
A greeting set here is used from the flow's next call; nothing has to be published. If the flow has unpublished changes from the call flow editor, the editor and [Get Call Flow](/v1/api-reference/endpoints/flows/call-flows/get) keep showing that draft's greeting, and publishing the draft replaces the greeting you set here. Sending a Get Call Flow response back while such changes exist replaces the live greeting with the draft's, including one you set through the API.

Dashboard test calls also use the draft's greeting until the draft is published or discarded. Demo links marked Draft always use their draft's greeting. Calls received on the flow's phone number, calls the flow places and other Web SDK calls use the greeting set here.
</Note>

### Errors

When a request is refused, nothing is changed.

| Status | Body | When |
| --- | --- | --- |
| `400` | `{"error": "Workspace ID is required."}` | No `x-workspace-id` |
| `400` | `{"message", "errors"}` | A changed `settings.callSetting` value is outside the allowed values above, or the silence sequence is longer than `maxCallDuration` |
| `400` | `{"message", "code", "field", "errors"}` | Greeting input is not valid (see `welcomeMessageConfig`) |
| `400` | `{"message": "..."}` | Other settings rules: invalid transfers, custom tools, booking link, Google Calendar settings or speech-recognition keywords, or a knowledge base from another workspace |
| `409` | `{"code": "FLOW_ARCHIVED", "message": "This flow is archived and is read-only. Restore it to make changes."}` | The flow is archived. Restore it in the dashboard first |
| `409` | `{"message": "Flow has been updated by another user"}` | You sent `expectedUpdatedAt` and the flow changed since then |
| `500` | `{"message": "Error updating flow"}` | No flow with that ID in this workspace, a malformed ID, or a body the flow cannot store (for example webhook `headers` sent as an object). This endpoint does not currently return `404` for an unknown flow |
