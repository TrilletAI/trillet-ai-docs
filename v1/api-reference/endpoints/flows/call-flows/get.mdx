---
title: "Get Call Flow"
api: "GET /v1/api/call-flows/{id}"
description: "Retrieve a specific call flow by its ID."
---

### Headers  

<ParamField header="x-workspace-id" type="string" required>
  Workspace identifier for the API.
</ParamField>

### Path Parameters

<ParamField path="id" type="string" required>
  The unique ID of the call flow.
</ParamField>

If the flow has unpublished changes from the call flow editor (an active draft), the response is that draft merged over the live flow, for every setting, not only the greeting. Calls received on the flow's number keep using the live version until the draft is published.

### Errors

| Status | Body | When |
| --- | --- | --- |
| `400` | `{"error": "Workspace ID is required."}` | No `x-workspace-id` |
| `500` | `{"message": "Error fetching flow"}` | No flow with that ID in this workspace, or a malformed ID. This endpoint does not currently return `404` |

### Response Fields

<ResponseField name="_id" type="string">
  The unique identifier for the call flow.
</ResponseField>

<ResponseField name="workspaceId" type="string">
  The identifier of the workspace where the call flow is configured.
</ResponseField>

<ResponseField name="name" type="string">
  The name assigned to the call flow.
</ResponseField>

<ResponseField name="direction" type="string">
  `outbound` or `bidirectional` (answers inbound calls and can place outbound ones).
</ResponseField>

<ResponseField name="description" type="string">
  A brief description of what the call flow is designed to handle.
</ResponseField>

<ResponseField name="agent" type="object">
  The agent the flow uses, as a full agent object (`_id`, `name`, `ttsModel`, `llmModel`, `sttProvider`, `phoneNumberIds` and so on). Use `agent._id` for the agent's ID. It is `null` if the flow has no agent.
</ResponseField>

<ResponseField name="folderId" type="object">
  The folder the flow is in, as `{ _id, name, icon, color }`, or `null`.
</ResponseField>

<ResponseField name="archivedAt" type="string">
  When the flow was archived, or `null`. An archived flow is read-only: [Update Call Flow](/v1/api-reference/endpoints/flows/call-flows/update) returns `409` until it is restored in the dashboard.
</ResponseField>

<ResponseField name="promptType" type="string">
  `simple` (one prompt drives the call), `nodes` (a node-based flow) or `flow` (legacy).
</ResponseField>

<ResponseField name="flowData" type="object">
  Contains the configuration of nodes and edges defining the call routing logic.
  <ResponseField name="nodes" type="array">
    An array detailing each node in the call flow.
  </ResponseField>
  <ResponseField name="edges" type="array">
    An array detailing the edges connecting the nodes.
  </ResponseField>
</ResponseField>

<ResponseField name="prompt" type="string">
  The initial or system prompt that is presented in the call flow.
</ResponseField>

<ResponseField name="isActive" type="boolean">
  Indicates whether the call flow is currently active.
</ResponseField>

<ResponseField name="settings" type="object">
  The configuration settings for the call flow, including knowledge bases, security and call settings. [Update Call Flow](/v1/api-reference/endpoints/flows/call-flows/update) describes each one.
  <ResponseField name="knowledgeBases" type="array">
    An array of references to knowledge bases included in the call flow.
  </ResponseField>
  <ResponseField name="security" type="object">
    Security settings relevant to the call flow.
    <ResponseField name="hipaaCompliance" type="boolean">
      Indicates whether HIPAA compliance is enabled.
    </ResponseField>
  </ResponseField>
  <ResponseField name="callSetting" type="object">
    Call length and silence handling.
    <ResponseField name="maxCallDuration" type="number">
      The longest a call can last, in seconds.
    </ResponseField>
    <ResponseField name="endCallOnSilence" type="number">
      Seconds of caller silence before the agent checks in ("Check in after" in the editor). It does not end the call by itself; see `silenceReminderRetries` and `endCallAfterReminder` on [Update Call Flow](/v1/api-reference/endpoints/flows/call-flows/update).
    </ResponseField>
  </ResponseField>
  <ResponseField name="welcomeMessageConfig" type="object">
    How the agent opens a call: an `Inbound` and an `Outbound` greeting, each with `selected`, `customMessage`, `aiGreetingPrompt`, `userFirstFallbackDelaySeconds` and `userFirstFallbackMessage`. Some flows can be missing a direction, a field, or the whole object; a missing `selected` means `aiFirst`. [Update Call Flow](/v1/api-reference/endpoints/flows/call-flows/update) explains each field and how to change it.

    Some older flows also return `welcomeMessage` and `customWelcomeMessage`, at the top level or inside `settings`. Nothing reads them; the greeting is `welcomeMessageConfig`.

    If the flow has unpublished changes from the call flow editor, this shows that draft's greeting instead of the live one.

    <ResponseField name="Inbound" type="object">
      The greeting for calls received on the flow's phone number.
    </ResponseField>
    <ResponseField name="Outbound" type="object">
      The greeting for calls the flow places and for web calls made with the Web SDK.
    </ResponseField>
  </ResponseField>
</ResponseField>

<ResponseField name="createdAt" type="string">
    Timestamp when the call flow was created.
</ResponseField>
<ResponseField name="updatedAt" type="string">
    Timestamp when the call flow was last updated.
</ResponseField>
