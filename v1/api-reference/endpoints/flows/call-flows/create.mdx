<ParamField body="welcomeMessage" type="string">
  A shortcut that gives both directions, `Inbound` and `Outbound`, the same greeting type. To set each direction separately or to use the other greeting options, send `settings.welcomeMessageConfig` instead. The value is case-sensitive:

  - `aiFirst` or `ai_dynamic`: the AI writes the greeting. Saved as `aiFirst` (AI Generated in the editor).
  - `customMessage` or `ai_custom`: the agent opens with the text in `customWelcomeMessage`. Saved as `customMessage` (Custom Message in the editor).
  - `userFirst` or `user_initiated`: the agent waits for the caller to speak first. Saved as `userFirst` (Wait for Caller in the editor).

  Any other value returns `400` with `code: "GREETING_TYPE_INVALID"`, and the flow is not created.

  If you send no greeting, both directions use `aiFirst`. Earlier versions of this page said the default was `user_initiated`. It is `aiFirst`, and `user_initiated` makes the agent wait for the caller to speak first.

  The shortcut is saved into `settings.welcomeMessageConfig`, so `welcomeMessage` and `customWelcomeMessage` are not stored and do not come back in the response. You can also send both fields inside `settings`. If you send a field in both places, the top-level value wins. If the request also includes `settings.welcomeMessageConfig`, the shortcut is ignored.
</ParamField>

<ParamField body="customWelcomeMessage" type="string">
  The text the agent says for a `customMessage` greeting, saved as `customMessage` in both directions. If you send non-blank text without `welcomeMessage`, the greeting type is set to `customMessage`.

  When the greeting type is `customMessage`, this text must not be blank. Otherwise the request returns `400` with `code: "GREETING_TEXT_REQUIRED"`, and the flow is not created.
</ParamField>

<ParamField body="settings" type="object">
  Main configuration object for the call flow.

  <Expandable title="settings">
    <ParamField body="welcomeMessageConfig" type="object">
      How the agent opens a call, set separately for each direction. The keys `Inbound` and `Outbound`, the field names and the `selected` values are case-sensitive.

      - `Inbound` is used for calls received on the flow's phone number.
      - `Outbound` is used for calls the flow places and for web calls made with the Web SDK. A flow with `direction: "outbound"` only uses `Outbound`, and an older flow with `direction: "inbound"` uses `Inbound` for these calls too.
      - Test calls from the dashboard, and calls started with [Connect a Web Call](/v1/api-reference/endpoints/calls/web/connect), use `Inbound`, except on an outbound-only flow, where they use `Outbound`. Unless the flow is outbound-only, you can switch a dashboard test call to `Outbound`.

      Fields you leave out keep their defaults, so you can send one direction, or only `selected` and `customMessage`. The greeting is used from the flow's first call; nothing has to be published.

      `settings.welcomeMessage` and `settings.customWelcomeMessage` are the same shortcut as the top-level `welcomeMessage` and `customWelcomeMessage`.

      If any greeting input is not valid, the flow is not created. The response is a `400` that lists every problem at once, with the body `{ "message", "code", "field", "errors" }`: `errors` has one message per problem, `message` joins them, and `code` and `field` describe the first one.

      - `400` with `code: "GREETING_TYPE_INVALID"`: `selected` is not `aiFirst`, `customMessage` or `userFirst`, or `welcomeMessage` is not one of its accepted values.
      - `400` with `code: "GREETING_FIELD_UNKNOWN"`: a direction key other than `Inbound` or `Outbound` (such as `inbound`), a direction field other than the five below, a greeting setting such as `welcomeMessageConfig` or `welcomeMessageDelay` sent outside `settings`, or a greeting-like name that the API does not use, such as `greeting` or `firstMessage`.
      - `400` with `code: "GREETING_VALUE_INVALID"`: `welcomeMessageConfig` or a direction is not an object, a text field (including `customWelcomeMessage`) is not a string, or `userFirstFallbackDelaySeconds` is not a number from 1 to 30.
      - `400` with `code: "GREETING_TEXT_REQUIRED"`: a direction's `selected` would be `customMessage` while its `customMessage` text is blank.

      <Expandable title="welcomeMessageConfig">

            </ParamField>
            <ParamField body="customMessage" type="string">
              What the agent says when `selected` is `customMessage`. It must not be blank for that type. `{{variable}}` placeholders are filled in on each call. Defaults to `""`.
            </ParamField>
            <ParamField body="aiGreetingPrompt" type="string">
              Instructions for the greeting the AI writes when `selected` is `aiFirst`. If empty, the AI writes the greeting from the flow's prompt. Defaults to `""`.
            </ParamField>
            <ParamField body="userFirstFallbackDelaySeconds" type="number">
              When `selected` is `userFirst`, how many seconds the agent waits for the caller to speak (Waiting timeout in the editor): a number from 1 to 30. Defaults to `10`.
            </ParamField>
            <ParamField body="userFirstFallbackMessage" type="string">
              When `selected` is `userFirst`, what the agent says if the caller is still silent after the wait (Fallback message in the editor). If it is empty, the agent says "Hello", but only when the wait is shorter than `settings.callSetting.endCallOnSilence`; otherwise the flow's usual silence handling applies. Defaults to `""`.
            </ParamField>
          </Expandable>
        </ParamField>
        <ParamField body="Outbound" type="object">
          The greeting for calls the flow places and for web calls made with the Web SDK.
          <Expandable title="Outbound">
            <ParamField body="selected" type="string">
              How the agent opens the call: `aiFirst` (AI Generated in the editor), `customMessage` (Custom Message) or `userFirst` (Wait for Caller). The older names `ai_dynamic`, `ai_custom` and `user_initiated` only work in the `welcomeMessage` shortcut. Defaults to `aiFirst`.
            </ParamField>
            <ParamField body="customMessage" type="string">
              What the agent says when `selected` is `customMessage`. It must not be blank for that type. `{{variable}}` placeholders are filled in on each call. Defaults to `""`.
            </ParamField>
            <ParamField body="aiGreetingPrompt" type="string">
              Instructions for the greeting the AI writes when `selected` is `aiFirst`. If empty, the AI writes the greeting from the flow's prompt. Defaults to `""`.
            </ParamField>
            <ParamField body="userFirstFallbackDelaySeconds" type="number">
              When `selected` is `userFirst`, how many seconds the agent waits for the caller to speak (Waiting timeout in the editor): a number from 1 to 30. Defaults to `10`.
            </ParamField>
            <ParamField body="userFirstFallbackMessage" type="string">
              When `selected` is `userFirst`, what the agent says if the caller is still silent after the wait (Fallback message in the editor). If it is empty, the agent says "Hello", but only when the wait is shorter than `settings.callSetting.endCallOnSilence`; otherwise the flow's usual silence handling applies. Defaults to `""`.
            </ParamField>
          </Expandable>
        </ParamField>
      </Expandable>
