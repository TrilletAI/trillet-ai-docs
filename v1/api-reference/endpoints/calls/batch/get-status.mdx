---
title: "Get Batch Status"
api: "GET /v1/api/batch-calls/{batchId}"
description: "Get status and counters for a batch call operation"
---

### Headers
<ParamField header="x-workspace-id" type="string" required>
  Workspace identifier for the API.
</ParamField>

### Path Parameters

<ParamField path="batchId" type="string" required>
  The 10-character batch ID returned by [Start Batch Calls](/v1/api-reference/endpoints/calls/batch/start).
</ParamField>

<Note>
  Live tracking for a batch is kept for **7 days**. After that, a batch that already ran returns `404 Batch not found`. Use [Call History](/v1/api-reference/endpoints/calls/call-history/list) filtered by `batchId`, or `GET /v1/api/batch-history/batch/{batchId}`, for older batches. A scheduled batch that hasn't started yet is always found.
</Note>

### Response

<ResponseField name="exists" type="boolean">
  Always `true` on a `200` response.
</ResponseField>

<ResponseField name="batchId" type="string">
  The batch ID.
</ResponseField>

<ResponseField name="status" type="string">
  Status worked out from the counters:
  - `scheduled` - The batch has a future start time and no calls have been queued yet
  - `queued` - Calls are waiting and none has completed yet
  - `processing` - Calls are being placed
  - `completed` - Nothing is waiting or active, and every job completed or failed
  - `failed` - Nothing is waiting or active, and every job failed
</ResponseField>

<ResponseField name="counters" type="object">
  Job counters for the batch.
  <Expandable title="Counters Object">
    <ResponseField name="waiting" type="number">
      Jobs waiting in the queue
    </ResponseField>
    <ResponseField name="active" type="number">
      Jobs currently being placed
    </ResponseField>
    <ResponseField name="completed" type="number">
      Dial jobs that finished. This doesn't mean the conversation succeeded; read the outcome from Call History.
    </ResponseField>
    <ResponseField name="failed" type="number">
      Dial jobs that failed
    </ResponseField>
    <ResponseField name="total" type="number">
      Total jobs in the batch
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="timestamp" type="number">
  Time this status was read, in Unix milliseconds.
</ResponseField>

<ResponseField name="progress" type="object">
  The same object [Get Batch Progress](/v1/api-reference/endpoints/calls/batch/get-progress) returns: `batchId`, `total`, `completed`, `failed`, `waiting`, `active`, `progress` (percent completed, 0-100) and `lastUpdated` (Unix milliseconds).
</ResponseField>

<ResponseField name="scheduledAt" type="string">
  Scheduled batches only. Start time as an ISO 8601 string.
</ResponseField>

<ResponseField name="scheduledTimezone" type="string | null">
  Scheduled batches only. The `scheduledTimezone` sent when the batch was created, or `null`.
</ResponseField>

<ResponseField name="timezone" type="string | null">
  Scheduled batches only. The call flow's office-hours timezone.
</ResponseField>

### Example Usage

```bash
curl -X GET "https://api.trillet.ai/v1/api/batch-calls/k3j9x0a1bq" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "x-workspace-id: YOUR_WORKSPACE_ID"
```

### Error Responses

<ResponseField name="error" type="string">
  Error message describing what went wrong
</ResponseField>

<ResponseField name="message" type="string">
  Additional context about the error
</ResponseField>

<ResponseField name="id" type="string">
  The batch ID that was not found (on some `404` responses)
</ResponseField>

**Common Error Codes:**
- `404` - `Batch not found`: the batch doesn't exist, belongs to another workspace, or its 7-day tracking window has passed
- `500` - Server error retrieving batch information

### Status Monitoring

Poll this endpoint to follow a running batch. For per-call outcomes, transcripts and analysis, use Call History filtered by `batchId`.
