---
title: "Cancel Batch Operation"
api: "DELETE /v1/api/batch-calls/{batchId}"
description: "Cancel a batch call operation and stop any remaining calls from being processed"
---

### Headers
<ParamField header="x-workspace-id" type="string" required>
  Workspace identifier for the API.
</ParamField>

### Path Parameters

<ParamField path="batchId" type="string" required>
  The 10-character batch ID to cancel
</ParamField>

<Note>
  Cancellation needs the batch's live tracking, which is kept for **7 days**. After that, cancelling a batch that already ran returns `404 Batch not found`. A scheduled batch that hasn't started can be cancelled.
</Note>

### Response

<ResponseField name="batchId" type="string">
  The ID of the cancelled batch
</ResponseField>

<ResponseField name="status" type="string">
  New status of the batch (will be "cancelled")
</ResponseField>

<ResponseField name="message" type="string">
  Confirmation message about the cancellation
</ResponseField>

<ResponseField name="details" type="object">
  Summary of the cancellation impact
  <Expandable title="Details Object">
    <ResponseField name="completedCalls" type="number">
      Number of calls that were already completed
    </ResponseField>
    <ResponseField name="failedCalls" type="number">
      Number of calls that had already failed
    </ResponseField>
    <ResponseField name="cancelledCalls" type="number">
      Number of calls that were cancelled (waiting + active)
    </ResponseField>
    <ResponseField name="totalCalls" type="number">
      Total number of calls in the batch
    </ResponseField>
  </Expandable>
</ResponseField>

### Example Usage

```bash
curl -X DELETE "https://api.trillet.ai/v1/api/batch-calls/k3j9x0a1bq" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "x-workspace-id: YOUR_WORKSPACE_ID"
```

### Example Response

```json
{
  "batchId": "k3j9x0a1bq",
  "status": "cancelled",
  "message": "Batch cancelled successfully",
  "details": {
    "completedCalls": 95,
    "failedCalls": 5,
    "cancelledCalls": 50,
    "totalCalls": 150
  }
}
```

### Cancellation Behavior

When you cancel a batch operation:

1. **Queued Calls**: Calls waiting in the queue are removed and will not be placed
2. **Active Calls**: Calls already in progress continue to completion, but no new calls start
3. **Completed Calls**: Already completed calls are not affected
4. **History**: The stored batch record is marked `cancelled`

### Error Responses

<ResponseField name="error" type="string">
  Error message describing what went wrong
</ResponseField>

<ResponseField name="message" type="string">
  Additional context about the error
</ResponseField>

<ResponseField name="id" type="string">
  The batch ID that was not found (for 404 errors)
</ResponseField>

**Common Error Codes:**
- `404` - `Batch not found`: the batch doesn't exist, belongs to another workspace, or its 7-day tracking window has passed. `Batch progress not found` when its counters can't be read.
- `500` - Server error during cancellation process

To stop a single contact instead of the whole batch, use [Cancel Batch Job](/v1/api-reference/endpoints/calls/batch/cancel-job) or [Cancel Batch Contact](/v1/api-reference/endpoints/calls/batch/cancel-contact).

### Use Cases

- Stop a batch operation that was started with incorrect data
- Cancel remaining calls when you've achieved your campaign goals
- Emergency stop for batch operations
- Cost control by stopping long-running batches

### Important Notes

- Cancellation cannot be undone, and the batch cannot be restarted
- Calls that were already placed are billed as usual
- Active calls at the time of cancellation finish normally
- `details` reflects the counters read just before cancelling
