---
title: "List Batch Calls"
api: "GET /v1/api/batch-calls/{batchId}/calls"
description: "Get a paginated list of all calls within a batch operation with optional status filtering"
---

### Headers
<ParamField header="x-workspace-id" type="string" required>
  Workspace identifier for the API.
</ParamField>

### Path Parameters

<ParamField path="batchId" type="string" required>
  The 10-character batch ID.
</ParamField>

### Query Parameters

<ParamField query="page" type="number" default="1">
  Page number for pagination (1-based)
</ParamField>

<ParamField query="limit" type="number" default="20">
  Number of results per page. No maximum is enforced.
</ParamField>

<ParamField query="status" type="string" default="all">
  Filter calls by status. Any other value matches the job's status exactly.
  - `all` - Return all calls regardless of status
  - `waiting` - Calls waiting in the queue
  - `active` - Calls being placed
  - `completed` - Dial jobs that finished
  - `failed` - Dial jobs that failed
  - `cancelled` - Jobs cancelled individually
</ParamField>

<Note>
  While the batch is tracked (7 days), jobs are read from the live queue. After that, the list is rebuilt from the stored batch record: `id` may then be the phone number when no job ID was stored, `call.duration` is filled in where known, and statuses come from the stored per-number results.
</Note>

### Response

<ResponseField name="jobs" type="array">
  Jobs in the batch.
  <Expandable title="Job Object">
    <ResponseField name="id" type="string">
      Job ID. Use it with Get Individual Call Status and Cancel Batch Job.
    </ResponseField>
    <ResponseField name="status" type="string">
      `waiting`, `active`, `completed`, `failed`, `cancelled` or `unknown`
    </ResponseField>
    <ResponseField name="phoneNumber" type="string">
      The number to call
    </ResponseField>
    <ResponseField name="contact" type="string | null">
      The row's `contact` or `name` column, if present (not `contact_name`)
    </ResponseField>
    <ResponseField name="business" type="string | null">
      The row's `business` or `company` column, if present
    </ResponseField>
    <ResponseField name="createdAt" type="number">
      Job timestamp in Unix milliseconds
    </ResponseField>
    <ResponseField name="data" type="object">
      `phoneNumber`, `record` (the CSV row) and `batchId`
    </ResponseField>
    <ResponseField name="call" type="object | null">
      `{ "duration": number }` when a duration is known, otherwise `null`
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="pagination" type="object">
  Pagination information
  <Expandable title="Pagination Object">
    <ResponseField name="page" type="number">
      Current page number
    </ResponseField>
    <ResponseField name="limit" type="number">
      Results per page
    </ResponseField>
    <ResponseField name="total" type="number">
      Total number of jobs matching the filter
    </ResponseField>
    <ResponseField name="totalPages" type="number">
      Total number of pages
    </ResponseField>
  </Expandable>
</ResponseField>

### Example Usage

```bash
# Get first page of all calls
curl -X GET "https://api.trillet.ai/v1/api/batch-calls/k3j9x0a1bq/calls" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "x-workspace-id: YOUR_WORKSPACE_ID"

# Get failed calls only, page 2
curl -X GET "https://api.trillet.ai/v1/api/batch-calls/k3j9x0a1bq/calls?status=failed&page=2&limit=50" \
  -H "x-api-key: YOUR_API_KEY" \
  -H "x-workspace-id: YOUR_WORKSPACE_ID"
```

### Error Responses

<ResponseField name="error" type="string">
  Error message describing what went wrong
</ResponseField>

**Common Error Codes:**
- `404` - `Batch not found`: the batch doesn't exist or belongs to another workspace
- `500` - Server error retrieving batch calls
